# HappyMac 🖥️

> 一个吸附在书桌背景板上的赛博小生命体。  
> 它不是工具，它只是在陪着你。

---

## 项目愿景

HappyMac 是一枚桌面像素交互小宠物，形态为冰箱贴。它极度克制、省电，平时几乎沉默，但在你需要的瞬间，能给出精准而温柔的回应。

它有自己的作息，有自己的情绪，会在你深夜还没睡的时候困着眼撑着陪你，也会在你发现它睡着的瞬间上演一出惊慌失措的假装没睡。

没有摄像头，没有麦克风，只有热量和微波的反射——它用这两样东西感受你的存在。

## 硬件架构

```
┌─────────────────────────────────────┐
│  OLED 1.3"  SH1106  128×64          │  ← 像素脸输出
│  ESP32-C3 SuperMini                 │  ← 核心大脑
│                                     │
│  能量分级感知系统                      │
│  ├─ 第一级：SR602 红外传感器           │  ← 哨兵，平时深度休眠
│  ├─ 第二级：LD2410C 毫米波雷达         │  ← 微动/能量/呼吸感知
│  └─ 第三级：LD2450 毫米波雷达          │  ← X/Y 双目标追踪
│                                     │
│  电源管理                            │
│  ├─ TP4056 双输入充电（USB-C + 太阳能）│
│  ├─ SS14 防反流二极管                 │
│  └─ AO3401 高侧开关（雷达电源门控）     │
└─────────────────────────────────────┘
```

### 为什么是两个雷达

LD2410C 和 LD2450 分工不同，互相不可替代：

| 传感器 | 擅长 | 在本项目中的角色 |
|--------|------|-----------------|
| LD2410C | 微动能量、呼吸、静止检测 | 判断用户状态（专注/发呆/睡着） |
| LD2450 | X/Y 坐标、多目标追踪、速度 | 判断用户位置和大幅度动作 |

## 交互设计

### 伪 3D 视差跟随

HappyMac 的脸由三个层次构成：双眼、鼻子、嘴巴。当用户位置偏移时，三个层次以不同幅度位移，形成视差效果：

```
用户向左移动时：
  鼻子  移动 ±6px   （最前层，移动最大）
  眼睛  移动 ±4px   （中层）
  嘴巴  移动 ±2px   （最后层，移动最小）
```

在 2D 屏幕上实现"它在转头盯着你"的视觉感受，无需 3D 硬件。

### 状态机

```
用户出现         → 慢慢从睡眠中醒来
用户看它         → 惊喜/脸红/眼睛睁大
用户发呆         → 跟着一起发呆，眼神涣散
用户长时间不理   → 打哈欠 → 揉眼 → 亮度渐暗 → 睡眠呼吸动画
深夜用户还在     → 困意动画，但撑着陪你
用户离位         → 目送 → 等待 → 睡着
被发现在睡觉     → 惊醒 → 假装没睡
```

### 睡眠状态的设计原则

全黑 = 坏掉了。HappyMac 睡着时：
- 亮度降至 20%，不是 0
- 慢速呼吸闪烁，表示有生命迹象
- 有人靠近时先有微小反应，再慢慢睁眼

## TinyML 训练路径（盲眼剑客计划）

最终产品绝对不包含摄像头，但训练阶段需要视觉作为 Ground Truth。

### 三步走

**第一步：师徒结对（数据采集）**

引入电脑摄像头作为"上帝视角"。MediaPipe 实时识别头部姿态和注视方向，自动打标签；同步记录同一时刻的雷达波形和红外特征。标注过程完全自动，用户正常使用电脑即可完成被动采集。

**第二步：炼丹提取（模型训练）**

将多模态数据输入神经网络，训练两个独立模型：

```
模型 A：位置动作分类
  输入：LD2450 的 X/Y + 帧间变化量
  输出：坐下/站立/前倾/后靠/左偏/右偏
  驱动：HappyMac 脸的朝向

模型 B：用户状态分类
  输入：LD2410C 能量值 + LD2450 速度辅助
  输出：专注/活跃/发呆/睡着/离位
  驱动：HappyMac 表情 + 屏幕亮度
```

两个模型时间尺度不同，分开训练，通过优先级仲裁层协同工作。

**第三步：过河拆桥（边缘部署）**

将模型量化部署进 ESP32-C3，彻底拔掉摄像头。设备仅凭热量和微波反射，凭直觉感受主人的目光。

### 实测发现

#### LD2450：正确安装后 X/Y 基础功能可用

- **正确安装方式**：PCB 竖直，天线阵列水平（与网上视频一致）
- **方向**：左移 X 减小，右移 X 增大（raw 数据）。OLED 显示已镜像，直觉一致
- **STILL σ≈107mm**：静止时 X 仍有慢漂（LD2450 固有限制，社区公认）
- **SWEEP σ≈222mm**：缓慢左右扫动信号是静止漂移的 2.1x——雷达能区分运动和静止
- **帧间精度**：静止时 ΔX 中位 1-2mm，但长时漂移可达 300-500mm
- **校准**：用户居中时 X≈0，偏左为负，偏右为正

#### LD2410C：静止检测正常，移动检测偏弱

- **Es>0 约 100%**：始终能检测到静止目标
- **Em 响应弱**：默认灵敏度阈值偏高，即使前后移动也难以触发
  - 固件已调高 gate 0-3 灵敏度至 80/100，但改善有限
  - 可能需要 HLKRadarTool app 手动配置

#### USB 供电噪声

- S3 和 C3 插同一台电脑时，C3 雷达数据严重劣化（Yσ 从 29mm → 290mm）
- 解决方案：S3 走 WiFi AP 模式，不与 C3 共用 USB 总线

#### 摄像头-雷达时间戳对齐

- 软件同步（SYNC 握手）未能精确对齐——两个独立时钟，相关分析始终 r≈0
- 需硬件同步：一根 GPIO 线让 C3 触发 S3 录像，或共用同一个外部时钟源
- **但对 TinyML 影响有限**：雷达数据本身（Y 准、X 趋势可用、Es 稳定）已经足够训练

## 已知限制与开放问题

### 双雷达同频干扰

LD2410C 和 LD2450 均在 24GHz ISM 频段工作，两台雷达同时开启时会产生**双向电磁干扰**：

| 干扰方向 | 影响 |
|----------|------|
| LD2450 → LD2410C | 底噪抬高 3-10dB，远距离检测灵敏度下降 |
| LD2410C → LD2450 | 相位干涉精度下降，X 轴坐标漂移加剧 |

**无法通过软件分时解决：** 两个雷达模块均不支持休眠/唤醒指令。断电重启需要数秒的启动+校准时间，无法在采集周期（100ms）内完成切换。硬件 MOSFET 电源门控（AO3401 + GPIO）是实现真正分时的唯一方案，目前尚未实施。

### X 轴精度与距离的耦合

LD2450 的 X 坐标通过两天线相位干涉计算（天线基线 ~6mm）。X 精度正比于目标距离：
- **< 0.5m：** X 基本为噪声，仅能做"左/中/右"粗分类
- **0.5-1m：** X 可用但漂移显著（σ≈200-1000mm）
- **> 1m：** 角分辨率进入可用区间

### 学术界与实践空白

在 **24GHz 低成本双雷达（<50 元）+ TinyML 跨模态蒸馏（视觉→雷达）** 这个细分领域，目前没有找到直接对标的论文或开源项目：

- LD2410/LD2450 DIY 社区项目均使用纯阈值规则，无 ML
- 60GHz+ 雷达的 TinyML 研究使用高分辨率热力图输入（CNN/Transformer），与本项目的 18 维时序标量特征（MLP）不可比
- 唯一的相近硬件栈论文（DOAJ, 2024）做的是"雷达触发→ESP32-S3 推理人脸识别"，不是行为分类

**本项目从数据采集到模型部署的完整跨模态蒸馏管线（collect.py → preprocess.py → train.py → C 头文件 → C3 推理）为自行设计，无成熟参考架构。**

### TinyML 管线限制

- **MediaPipe 标签质量**：训练标签来自 MediaPipe 面部网格的几何推导（头部位姿、注视方向），不是人工标注。标签存在系统性偏差
- **ESP32-C3 推理性能**：RISC-V 核心无 SIMD 指令扩展，MLP 推理约 <10ms（2 层, <2K 参数），但无法运行 CNN 类模型。如需更复杂模型，需迁移至 ESP32-S3（ESP-NN 加速 42x）
- **数据采集一次性**：相机仅存在于训练期。如果雷达安装位置/朝向改变，需要重新采集数据

## TinyML 管线

```
training/
├── config.py           # 全局配置（特征列表、窗口参数、标签定义等）
├── collect.py          # 数据采集：S3 视频流 + C3 串口 + MediaPipe 标注
├── preprocess.py       # 特征工程：滑动窗口 + 18 维特征提取 + 标签生成
├── train.py            # 训练：RF 快速验证 → MLP 训练 → INT8 量化 → C 头文件
├── requirements.txt    # Python 依赖
├── face_landmarker_v2_with_blendshapes.task  # MediaPipe 模型（首次运行时自动下载）
├── sessions/           # 原始采集数据（CSV）
└── models/             # 训练产物（.npy, .h5, .tflite, .h）
```

### 数据流

```
[采集]  collect.py
  S3 MJPEG 视频流 ──→ MediaPipe Face Landmarker ──→ 头部位姿 + 注视方向 + 眼部开合
  C3 USB 串口     ──→ LD2450(X/Y/V) + LD2410C(Em/Es) + SR602 ← 时间对齐 → 一行 CSV

[处理]  preprocess.py
  原始 CSV → 滑动窗口(2s/5s) → 18维特征向量 → 模型A标签(8类) + 模型B标签(8类)
  → X_a.npy / y_a.npy / X_b.npy / y_b.npy

[训练]  train.py
  Random Forest 验证(准确率>85%才继续) → MLP(32→16→softmax) → INT8 量化 → model_*.h
```

## 设计哲学

> 它不应该每天都需要你。  
> 但当你抬头的那一刻，它刚好也在看你——  
> 这就够了。

隐私优先：无摄像头，无麦克风，无联网，无云端。感知只发生在本地，数据从不离开桌面。

省电优先：三级唤醒结构，绝大多数时间处于深度休眠。太阳能辅助充电，真正的低打扰存在。

克制优先：去掉所有工具属性（无时钟、无天气、无通知推送），只保留陪伴本身。
