# 数据采集规范 V2 —— 装壳后的正式采集（下半场）

> 适用时机：**产品装配（外壳/安装位）确定之后**。
> 雷达安装几何一变，V1 数据（`sessions/` 里 2026-08 的 8 个训练会话）即不可再用作主训练集——这是 README「TinyML 管线限制」里写明的既有结论。
> 本文档是采集的**唯一执行规范**：开工前通读一遍，现场照 SOP 走，结束后照质量门验收。

---

## 0. 为什么是 V2（背景与目标）

V1 数据体检（2026-08-30）发现的问题，本轮必须修复，否则重训没有意义：

| # | V1 问题 | 体检证据 | V2 对策 |
|---|---------|----------|---------|
| 1 | 规则场次视频全部倒装（5/5） | 抽帧目检，人脸 180° 倒置 | 工装固定朝向 + 开录首帧人工确认（§3.4） |
| 2 | Es 会话间漂移（中位 37~61），而 Es 是头号特征（重要性 0.346） | 各会话 summary 对比 | 几何登记 + 静置规范 + 每场空桌面基线（§2、§4） |
| 3 | 自由数据 LATERAL 样本稀缺（154~547 帧，少 3~10 倍） | aligned 标签分布 | 新增 `big_sway` 动作块 + 自由会话保底要求（§3.2） |
| 4 | em 全场报废（>0 帧仅 0.9~4.5%），2410 被阈值 80 调聋 | em 统计 | 采集固件灵敏度调到 40/40，质量门验证（§1、§5） |
| 5 | 只记录第一个雷达目标，头部分辨目标被丢弃 | parse2450 逻辑 | 记录全部 3 目标（§1.2） |

V2 要回答的问题（按优先级）：
1. 装壳几何下，现有 5 类（ABSENT/STILL/LATERAL/APPROACH/RETREAT）模型要重训——提供主训练集；
2. **转头可分性**：调敏后的 em + 3 目标数据，能否把 head_only 从 typing/still 里分出来（`exp_head_separability.py` 验收，见 §7）；
3. 距离因素显式化：近场（0.5m）/远场（1.5m）分开采样，给阈值调参提供依据。

## 1. 采集前固件与工具准备（前置条件，缺一不开工）

### 1.1 采集固件（new_radar.ino 或新开 collection_v2 分支）改动
- [ ] LD2410C gate 0-3 灵敏度阈值 **80/80 → 40/40**（V1 值也保留为编译期宏，方便对照实验）
- [ ] `parse2450` 输出**全部 3 个目标**：CSV 列扩展为
      `t_global,x,y,v,x2,y2,v2,x3,y3,v3,em,es,action`（无第二/三目标时填 0）
- [ ] 固件版本号 `FW_VERSION` 宏，串口启动时打印，写入 CSV 首行注释或 meta
- [ ] S3 竖直朝向固定（加装定位件），`/status` 返回 orientation 字段

### 1.2 上位机（collect.py）
- [ ] 支持新的 3 目标 CSV 列
- [ ] 每场自动写 `_meta.json`：固件版本、灵敏度配置、orientation、几何登记（§2.3）、噪声基线
- [ ] 结束时自动跑质量门快检（§5），终端直接显示 PASS/FAIL

### 1.3 版本冻结纪律
- 采集轮次期间**禁止**改任何固件参数/灵敏度/安装几何；确需改动 → 当前会话作废、meta 记录变更、重新开始本轮
- 模拟器噪声模型（`happymac_sim.html` FW 区）在本轮第一场数据验收后重新标定一次

## 2. 环境与工装规范

### 2.1 雷达静置（2026-08-09 实验规范，继续执行）
上电后**静置 ≥2 分钟**再开始记录，期间天线对空桌面/空墙自运行。冷启动异常跳动只记入 meta 备注，不进入训练数据。

### 2.2 供电
C3 独立 USB 口或独立电源，**不与 S3 共用同一 USB 总线**（V1 教训：共用时 Yσ 从 29mm 劣化到 290mm）。S3 走 WiFi AP 模式。

### 2.3 几何与环境登记（写入 meta.json，缺项不得开工）
- 雷达安装高度（mm）、俯仰角、朝向方位、距桌面边缘距离
- 装壳状态：裸板 / 装壳（壳材质）
- 房间、桌面材质、1m 内主要反射物
- 拍照 2 张：雷达安装特写 + 全局摆位

### 2.4 视频朝向确认
开录后第 1 帧，人工确认人脸**正立**（V1 倒装教训）。不确认不继续。

## 3. 会话内容计划

每轮 = **1 空桌基线 + 1 规则会话 + 1 自由会话**。正式采集 ≥2 轮（不同天各一轮）。

### 3.1 空桌基线（新增，V1 没有）
无人在场录 60s。用途：ABSENT 类的真值基线 + 当场噪声底标定。

### 3.2 规则会话（约 6 分钟，HUD 引导，沿用倒计时模板）

| 动作块 | 时长 | 说明 |
|---|---|---|
| still_30s | 30s | 静坐基线 |
| natural_typing | 45s | **加长**（V1 是 27s；STILL 边界的重灾区，多给数据） |
| slow_sweep | 20s | 缓慢左右躯干移动 |
| quick_points | 20s | 快速指点 |
| ellipse | 20s | 画椭圆 |
| fwd_back | 20s | 前倾后靠 |
| head_only | 30s | **加长**：转头看雷达方向 ×6 次 + 左右看 ×6 次（转头研究主数据） |
| **turn_toward**（新增） | 20s | 随机间隔突然转头看雷达，带轻微身体前倾（模拟"被它抓住注意"） |
| **big_sway**（新增） | 20s | 大幅左右重心移动 ±50cm（补 LATERAL 坑） |
| **still_near / still_far**（新增） | 15s+15s | 0.5m 与 1.5m 各静坐一段（距离显式采样） |
| natural_reach | 20s | 伸手取物 |
| stand_sit | 20s | 起身坐下 |

### 3.3 自由会话（5 分钟 × 每轮 1 场）
正常用电脑即可（被动采集），但**保底要求**：
- 至少一段明显左右移动（≥30cm）≥20s——保 LATERAL
- 至少一次起身离开画面 ≥10s 再回来——保 ABSENT/GOODBYE 语义
- 至少一次从远处走近再坐回——保 APPROACH
- 深夜时段若条件允许加采 1 场（作息调制的验证数据）

### 3.4 轮次与总量
- ≥2 轮、跨 ≥2 天；每轮产出 ≈1 规则 + 1 自由 + 1 基线
- 窗口产出估算（2s 窗 / 0.5s 步）：规则每场 ≈260 窗、自由每场 ≈590 窗、2 轮合计 ≈2700 窗（V1 为 1185 规则窗 + 自由窗）
- 验收目标：**每个训练类 ≥600 窗**（V1 的 LATERAL 远低于此）

## 4. 现场执行 SOP（每场照做）

1. 上电，静置 ≥2 分钟（手机倒计时），期间确认视频朝向（§2.4）
2. 录 60s 空桌基线（无人在 3m 内）
3. 人员入位，串口发 `!CAL` 校准中心
4. 开始规则会话（HUD 引导）或自由会话（按 §3.3 保底清单执行）
5. 全程禁止：插拔 USB、改波特率、开启动画固件、挪动雷达
6. 结束后**当场**跑质量门快检，FAIL 项当场重采（人还在、姿势还热）

---

## 5. 质量门（每场验收标准，全部 PASS 才算数）

| 检查项 | 阈值 | 来源 |
|---|---|---|
| 帧率 | ≥14Hz（实测应 ≈16.2） | V1 基线 |
| 空窗 | >1s 的间隙 = 0 | V1 达标项，保持 |
| em 活性 | em>0 帧占比 ≥10% | 验证调敏生效；不达标先查灵敏度 |
| 3 目标列 | 第二/三目标列在多人/转头段非全零 | 验证新 parse |
| 静坐噪声 | still 段 \|x\| σ ≤150mm | V1 实测区间 |
| 对齐有效 | 规则 ≥80%，自由 radar_valid ≥95% | V1 水平 |
| 视频朝向 | 正装、人脸完整、HUD 可读 | 倒装教训 |
| 标签下限 | LATERAL ≥600 帧/轮；HEAD/TURN 相关块完整执行 | 补坑目标 |
| 基线 | 空桌 60s 存在且 es 接近 0 | 新增项 |

FAIL 处理：当场重采一次；仍 FAIL → 记录原因、跳过该项继续（数据留档不进训练集），当天结束后统一排查。

## 6. 数据管理与命名

- 新数据一律放 **`sessions_v2/`**；V1 的 `sessions/` 冻结只读
- 命名沿用 `session_YYYYMMDD_HHMMSS.csv`，附属文件同 V1 约定（_aligned / _vidts / _meta）
- `_meta.json` 新增字段：`fw_version`、`sensitivity`、`orientation`、`geometry{height,pitch,azimuth,edge_dist}`、`shell`、`noise_baseline{es_med,x_std_still}`
- 大文件（mp4/csv）不入 git（沿用现有 .gitignore），**summary/meta 必须入库**
- 每轮收工：跑 `align_all_sessions.py` 生成 aligned → 跑体检脚本复核 → 提交 summary

## 7. 采集后验收 → 重训决策链

```
质量门全 PASS
  ↓
① 用 V2 数据重标定模拟器噪声模型（happymac_sim.html FW 区）
  ↓
② python3 exp_head_separability.py   ← 转头可分性验收
     HEAD 召回 >75% 且 TYPING→HEAD 误报 <10%
     ├── 达标 → 新增 HEAD 类，走完整重训（export_tree.py 出 C+JS）
     └── 不达标 → 转头产品化搁置，维持"小幅动作归 STILL"（2026-08-30 决策）
  ↓
③ eval_replay.js 用新树全量回归
     静坐误笑率目标 <10%（当前 V1 树为 16.6%）
  ↓
④ 重训通过 → 固件换树、模拟器同步、烧录、真机对拍
```

## 8. 已知风险与预案

- **调敏副作用**：2410 灵敏度 40 可能推高运动误报 → 重采后用 `eval_replay.js --sweep` 重扫 MOTION/confirm 参数
- **壳体散射未知**：预算允许时加采一场"裸板 vs 装壳"同协议对照，量化壳的影响（也可作为论文素材）
- **转头还是不可分**：按 2026-08-30 决策，产品上搁置转头反应，不硬凑
- **双雷达互扰**：硬件固有（AO3401 电源门控仍未实施），本规范通过"es 基线登记 + 每场静置"控制其可变性，不试图消除
